为什么换色不够

原版和 fork 共享的不只是颜色——是整条信息骨架。用户扫一眼页面结构就能认出来。

原版骨架（一眼认出）
从上到下的线性结构：
① 顶部 Hero（Logo + 标题 + 状态）
② 横向滚动 Tab 栏
③ 筛选条（精选/全量 + 搜索）
④ 热点排行（编号列表）
⑤ 时间轴卡片流（左竖线 + 右卡片）
⑥ WaytoAGI 社区板块

✗ 这个骨架就是原版的指纹。
✗ 换任何颜色，骨架一样 = 一眼 fork。
✗ 卡片样式、Tab 交互、筛选模式完全一致。
重构骨架（完全陌生）
左右分栏 + 棋盘格布局：
① 左侧栏：品牌 + 角色导航 + 状态
② 顶部条：搜索 + 模式切换（紧凑）
③ 每日简报卡（今日摘要 + 数据）
④ Bento 棋盘格（热点/角色/新闻/健康/活动）
⑤ 无时间轴、无横向 Tab、无 Hero 大图

✓ 布局完全不同，截图对比无法识别。
✓ 信息组织从线性→空间化。
✓ 独有组件：每日简报、角色状态、活动热力图。

3

设计原则

四个原则指导所有视觉和交互决策

🏭

工坊控制台

界面是维克托的工坊仪表盘——侧栏、面板、数据环，像操作一台精密机器，不是刷信息流。

🧩

棋盘格节奏

告别单列时间轴。用大小不同的卡片拼成棋盘，信息密度更高，视觉节奏更丰富，和原版的线性排列完全不同。

🤖

角色即导航

角色不只是装饰——它们就是导航系统。提莫=全部信源，黑默丁格=精选，吉格斯=热点。用户通过角色理解功能。

📡

每日简报 = 品牌记忆

首屏的「维克托今日简报」是原版没有的独有组件。它让每个来访者第一眼看到的就是品牌内容，而不是通用信息流。

数据层改动

好消息：底层数据文件完全复用，只在前端渲染层做差异化

不需要改 Python 脚本

scripts/update_news.py 生成的 JSON 文件（latest-24h.json、source-status.json、daily-brief.json 等）全部保留。 前端 JS 仍然 fetch 同样的数据文件，只是渲染方式完全不同。你可以选择：

方案 A：直接修改 index.html + styles.css + app.js，替换渲染逻辑。
方案 B（推荐）：新建一个 viktor/ 目录，放全新的 HTML/CSS/JS，数据 URL 指向同级的 data/。原版代码完全不动，方便对比和回退。

实施路线

四个阶段，每阶段独立可上线

Phase 1 · 骨架重建（2-3 天）

侧栏 + 顶部条 + Bento 格

彻底替换页面布局。这是区分 fork 最关键的一步。

  • 新建 viktor/ 目录，创建全新的 index.html
  • 实现左侧栏：品牌区 + 角色导航 + 底部状态
  • 实现顶部条：频道标题 + 搜索 + 模式切换
  • 实现 Bento 棋盘格布局（CSS Grid，6 列）
  • 数据 fetch 逻辑复用，只改渲染函数
Phase 2 · 独有组件（1-2 天）

每日简报 + 角色面板 + 健康环 + 热力图

实现 4 个原版没有的组件，彻底消除 fork 痕迹。

  • 每日简报卡：从 daily-brief.json 读摘要 + 从 latest-24h.json 算数据
  • 角色状态面板：根据当前频道切换角色和点评
  • 信源健康环：SVG 圆环 + source-status.json
  • 活动热力图：从历史数据聚合 30 天活动量
Phase 3 · 视觉打磨（1 天）

暗色主题 + 角色色 + 动效

在骨架和组件就位后，打磨视觉细节。

  • 墨黑底 + 电光橙强调色 + 角色专属色
  • 义眼 Logo 呼吸 glow 动画
  • 卡片 hover 效果（border glow + shadow）
  • 热点序号的金银铜发光效果
Phase 4 · 收尾上线（0.5 天）

响应式 + meta + 部署

  • 移动端适配：侧栏折叠为底部 Tab 或汉堡菜单
  • meta 标签全部更新（title / og / description）
  • GitHub Pages 部署验证
  • 原版 index.html 保留为 classic/index.html 备用
